# LabFlow — умная очередь на сдачу лабораторных

Студент за минуту записывается в очередь и видит своё место и примерное время ожидания.
Преподаватель вызывает студентов, перетаскивает их в очереди, запускает тест и фиксирует результат.
Подробное ТЗ — в [CLAUDE.md](CLAUDE.md).

## Возможности

**Студент**
- запись в очередь за 3 клика; выбранные лабы запоминаются;
- своё место, прогресс ожидания и время по часам («≈ 15 мин, около 10:45»);
- на главной — блок «Вы в очереди» с местом в каждой очереди;
- уведомления «Вы следующий» и «Вас вызвали!»: звук, вибрация, системное уведомление,
  мигающая вкладка (номер места виден прямо в заголовке вкладки);
- тест с таймером, прогрессом ответов и автоотправкой, когда время вышло;
- «Работа сдана ✓» с результатом теста, история и статистика в «Результатах».

**Преподаватель**
- живая очередь: перетаскивание, «Вызвать следующего» (клавиша <kbd>N</kbd>), <kbd>Esc</kbd>;
- таймер текущей сдачи с подсветкой, если студент сдаёт дольше плана;
- быстрые кнопки «Сдал / Не сдал» прямо в списке;
- прогноз: кто не успеет до конца пары;
- «Ссылка для записи» в один клик и **режим проектора** (`/board/:id`) для экрана в аудитории;
- статистика: итоги сдач, план/факт по длительности каждой лабы с советом, ведомость и
  выгрузка в **CSV** для Excel;
- «Через неделю» — создать такую же очередь на ту же пару; пресеты времени пар.

**Для всех**: светлая/тёмная/системная тема, адаптивный интерфейс (от 360 px, нижняя панель
вкладок на телефоне), уведомления о действиях, индикатор «нет интернета», страница 404.

## Быстрый старт

Нужны Python 3.12, Node 20+ и PostgreSQL 16. Подойдёт свой PostgreSQL или Docker:
`docker compose up -d db`. В базе нужны пользователь `labflow` с паролем `labflow` и база `labflow`.

**Самый простой способ** — одна команда из корня проекта. При первом запуске она сама
поставит зависимости, затем применит миграции и поднимет оба сервера:

```bash
cd ~/Документы/LabFlow
./dev.sh            # Ctrl+C — остановить
```

Вручную: backend и frontend — это два сервера, которые работают одновременно.
Каждый запускается **в своём терминале** из корня проекта.

**Первый запуск (один раз):**

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed          # демо-данные, необязательно
cd ../frontend
npm install
```

**Терминал 1 — backend** (http://localhost:8000/docs):

```bash
cd backend && .venv/bin/uvicorn app.main:app --reload
```

**Терминал 2 — frontend** (http://localhost:5173):

```bash
cd frontend && npm run dev
```

Если видите `Address already in use`, значит сервер на этом порту уже запущен.
Остановите его (Ctrl+C в его терминале) или откройте сайт по уже работающему адресу.

Весь стек в Docker: `docker compose up --build` → http://localhost:8080.

### Демо-аккаунты (после `python -m app.seed`)

| Роль | Логин | Пароль |
|---|---|---|
| Преподаватель | teacher | 1234 |
| Студент | student | 1234 |
| Администратор | admin | 1234 |

Простые пароли — только для локальной разработки. Новые пользователи регистрируются
по email как студенты; роль преподавателя выдаёт администратор.

## Проверки перед PR

```bash
cd backend && ruff check . && mypy app && pytest
cd frontend && npm run lint && npm run test && npm run build
```

Тесты backend по умолчанию идут на SQLite в памяти. Чтобы прогнать их на PostgreSQL:
`TEST_DATABASE_URL=postgresql+asyncpg://labflow:labflow@localhost:5432/labflow_test pytest`.

## Изменили API?

```bash
cd backend && python -m app.export_openapi openapi.json
cd frontend && npm run gen:api     # пересобирает src/api/schema.d.ts
```

CI проверяет, что `openapi.json` и типы фронтенда не устарели.

## Как устроено

- `backend/app/services/queue_engine.py` — алгоритм очереди (чистые функции):
  `key = D − k·W`, сортировка по возрастанию, закреплённые места, время ожидания.
  Через `D/k` минут ожидания запись обгоняет любую новую — бесконечного ожидания нет.
- `backend/app/services/queue_service.py` — загрузка из БД, пересчёт и рассылка по WebSocket.
- `backend/app/ws/` — `WS /api/v1/ws/queues/{id}?token=…`; пересчёт по таймеру раз в минуту.
- `frontend/src/hooks/useQueueState.ts` — WebSocket с автопереподключением;
  пока соединения нет, опрос раз в 5 секунд.
- Закреплённый преподавателем студент продвигается вместе с очередью: когда кто-то выше
  уходит, его место уменьшается на 1.

## Выкладка на Render (бесплатно)

Всё работает как **один веб-сервис**: сервер FastAPI отдаёт и собранный сайт, и API, и WebSocket
с одного адреса. Описание — в [render.yaml](render.yaml), сборка — в [Dockerfile](Dockerfile).

1. Залейте репозиторий на GitHub.
2. На [render.com](https://render.com) войдите через GitHub → **New → Blueprint** → выберите репозиторий.
3. Render покажет базу `labflow-db` и сервис `labflow` и спросит пароли демо-аккаунтов
   `SEED_ADMIN_PASSWORD`, `SEED_TEACHER_PASSWORD`, `SEED_STUDENT_PASSWORD`
   (пустой пароль — аккаунт не создаётся). Нажмите **Apply**.
4. Через 5–10 минут сайт откроется по адресу вида `https://labflow-xxxx.onrender.com`.

Важно знать про бесплатный тариф:
- сервис **засыпает после 15 минут без запросов**, первое открытие после этого — около минуты;
- бесплатную базу Render **удаляет примерно через 30 дней** — для постоянной работы нужна
  другая база (например, Neon): достаточно поменять переменную `DATABASE_URL`;
- после каждого `git push` в `main` Render пересобирает и выкладывает сайт сам.
