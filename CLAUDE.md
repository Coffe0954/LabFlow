# LabFlow — умная очередь на сдачу лабораторных

Веб-сервис для студентов и преподавателей МАИ. Студент за минуту записывается в очередь на сдачу лабы и видит своё место и примерное время ожидания. Преподаватель управляет очередью и запускает тест по лабе, пока смотрит код студента.

Команда М8О-312БВ-24, срок 14 недель (7 спринтов по Scrum), бюджет 0 ₽.

---

## 1. Цель и критерии успеха

**Цель:** сократить время ожидания на сдаче лаб и сделать процесс предсказуемым.

Продукт считается удачным, если:
- запись в очередь занимает **меньше 1 минуты** и несколько кликов;
- среднее ожидание **меньше**, чем в живой очереди;
- за одно занятие **больше студентов** успевают сдать работу;
- по опросу студенты и преподаватели оценивают сервис положительно.

## 2. Границы

**Делаем:**
- сортировку очереди по приоритетам и длительности сдачи;
- aging-модель: приоритет растёт, пока студент ждёт;
- ручную корректировку очереди преподавателем (перетаскивание);
- тесты по лабам: создание, запуск преподавателем, прохождение студентом;
- показ места в очереди и примерного времени ожидания;
- автообновление очереди в реальном времени;
- статистику (время ожидания, число сдавших);
- рекламный баннер;
- веб-интерфейс студента и преподавателя, адаптивный под телефон.

**НЕ делаем (не предлагать и не реализовывать):**
- мобильные приложения;
- платежи;
- интеграции с гос. системами и системами МАИ;
- полноценную LMS;
- поддержку других вузов;
- AI-проверку кода.

| Роль | Что может |
|---|---|

## 6. Модель данных

- `users` — id, email (уникальный), password_hash, full_name, group, role, created_at
- `disciplines` — id, title
- `labs` — id, discipline_id, number, title, expected_minutes
- `queues` — id, discipline_id, teacher_id, date, starts_at, ends_at, status (`open` | `closed`)
- `queue_entries` — id, queue_id, student_id, status, created_at, called_at, finished_at, pinned_position (nullable)
  - статусы: `waiting` → `called` → `testing` → `reviewing` → `passed` | `failed` | `left`
- `entry_labs` — entry_id, lab_id
- `tests` — id, lab_id, title, time_limit_min
- `questions` — id, test_id, text, kind (`single` | `multi` | `text`), options (jsonb), correct (jsonb)
- `test_attempts` — id, entry_id, test_id, started_at, finished_at, score
- `answers` — id, attempt_id, question_id, value (jsonb)
- `ad_banners` — id, image_url, link, active

Ограничения:
- один студент может иметь в одной очереди только одну активную запись;
- индекс по `(queue_id, status)` для быстрого пересчёта очереди;
- любые изменения схемы — только через миграции Alembic.

## 7. Алгоритм очереди — ядро продукта

Код лежит в `services/queue_engine.py`. Это чистая функция без обращений к БД, она обязательно покрыта unit-тестами.

**Входные данные:** записи со статусом `waiting` и текущее время.

1. **Длительность записи:** `D = сумма expected_minutes выбранных лаб`.
2. **Ожидание:** `W = now − created_at` (в минутах).
3. **Эффективный ключ:** `key = D − k · W`, по умолчанию `k = 0.5`. Коэффициент задаётся в настройках очереди.
4. **Сортировка** по `key` по возрастанию:
   - короткие сдачи идут раньше;
   - при равенстве раньше идёт тот, кто записался раньше.
5. **Aging.** Чем дольше студент ждёт, тем меньше его `key`. Через `D/k` минут он гарантированно обгоняет любую новую запись. Поэтому бесконечного ожидания нет.
6. **Ручная правка.** Если преподаватель задал `pinned_position`, запись стоит на этом месте. Остальные записи сортируются алгоритмом вокруг неё. Закрепление снимается, когда студента вызвали.
7. **Время ожидания** для позиции `i` = остаток времени у текущего сдающего + сумма `D` всех записей перед `i`. Показываем округлённо, например «≈ 25 мин».

**Когда пересчитывать:**
- при любой смене статуса;
- при записи или выходе студента;
- при перетаскивании;
- раз в минуту по таймеру, потому что с ростом `W` меняется `key`.

После пересчёта новое состояние рассылается всем подписчикам очереди по WebSocket.

**Обязательные тест-сценарии:**
- быстрая лаба обгоняет длинную;
- долго ждущий обгоняет новую короткую;
- закреплённая позиция сохраняется;
- пустая очередь;
- записи с одинаковым ключом;
- время ожидания считается верно.

## 8. API (REST, префикс `/api/v1`)

| Метод и путь | Кто | Что делает |
|---|---|---|
| `POST /auth/register`, `POST /auth/login`, `GET /auth/me` | все | регистрация, вход, текущий пользователь |
| `GET /queues`, `GET /queues/{id}` | все | список очередей, очередь с порядком и временем ожидания |
| `POST /queues`, `PATCH /queues/{id}` | teacher | создать или закрыть очередь, изменить `k` |
| `POST /queues/{id}/entries` | student | записаться, передать `lab_ids` |
| `DELETE /entries/{id}` | student (своя запись), teacher | выйти из очереди |
| `POST /queues/{id}/call-next` | teacher | вызвать следующего |
| `PATCH /entries/{id}/position` | teacher | закрепить позицию (drag-and-drop) |
| `PATCH /entries/{id}/status` | teacher | сменить статус, зафиксировать результат |
| `POST /entries/{id}/test/start` | teacher | запустить тест для студента |
| `POST /attempts/{id}/answers`, `POST /attempts/{id}/finish` | student | ответить на вопросы, завершить тест |
| `CRUD /labs`, `CRUD /tests`, `CRUD /tests/{id}/questions` | teacher | лабы, тесты, вопросы |
| `GET /queues/{id}/stats`, `GET /stats/me` | teacher / student | статистика |
| `GET /ads/active` | все | активный баннер |
| `WS /ws/queues/{id}` | все | поток обновлений очереди |

Документация Swagger генерируется автоматически по адресу `/docs` и должна совпадать с реальным API. Ответы с ошибками возвращаются в едином формате `{"detail": "..."}`.

## 9. Экраны фронтенда

**Студент:**
1. Регистрация и вход.
2. Список открытых очередей.
3. Запись: выбор лаб из списка и кнопка «Записаться».
4. Моя очередь:
   - список с моим местом, подсвеченным;
   - примерное время рядом с именем;
   - кнопка «Выйти».
5. Тест: вопросы, таймер, отправка ответов.
6. Мои результаты и статистика по тестам.

**Преподаватель:**
1. Создание очереди.
2. Очередь в реальном времени:
   - перетаскивание студентов;
   - «Вызвать следующего»;
   - смена статусов.
3. Карточка студента:
   - выбранные лабы;
   - «Запустить тест»;
   - результат теста;
   - «Сдал / не сдал».
4. Конструктор тестов.
5. Статистика очереди.

**Общее:**
- рекламный баннер не перекрывает очередь;
- экраны работают на ширине 360 px;
- запись в очередь укладывается в 3 клика после входа.

## 10. Пользовательский сценарий (end-to-end тест)

Регистрация → выбор очереди → «Записаться» → выбор лаб → подтверждение → ожидание с видимым местом и временем → преподаватель вызывает и запускает тест → студент проходит тест, пока преподаватель смотрит код → преподаватель фиксирует результат → очередь пересчитывается у всех.

## 11. Нефункциональные требования

- **Производительность:**
  - пересчёт и рассылка очереди занимают меньше 2 с;
  - сервис выдерживает одновременный заход всей группы в день сдачи.
- **Надёжность:**
  - сервис не падает во время пары;
  - при разрыве WebSocket клиент переподключается сам;
  - данные очереди не теряются.
- **Безопасность:**
  - HTTPS;
  - пароли хранятся только в виде bcrypt-хэша;
  - секреты лежат в переменных окружения, а не в коде;
  - права проверяются на сервере;
  - открытый API отдаёт персональные данные только в минимально нужном объёме.
- **Удобство:** запись занимает меньше 1 минуты, интерфейс понятен без инструкции.
- **Стоимость:** только бесплатные тарифы.

## 14. Правила работы с кодом

- **Ветки:** `main` защищена. Работаем в ветках `feature/<кратко>` и `fix/<кратко>`, сливаем через PR.
- **Ревью:** хотя бы один человек кроме автора.
- **Коммиты** в формате Conventional Commits: `feat: запись в очередь`, `fix: aging при пустой очереди`.
- **CI на каждый PR:** линтеры, проверка типов, тесты backend и frontend, сборка. Красный CI — PR не сливаем.
- **Выкладка:** после слияния в `main` — автоматически.
- **Миграции:** любое изменение моделей сопровождается миграцией Alembic в том же PR.
- **Контракт API:** при изменении API обновляем Pydantic-схемы и пересобираем типы на фронтенде.
- **Секреты** и `.env` не коммитим. В репозитории лежит только `.env.example`.

**Запуск локально:**
```bash
docker compose up -d db
cd backend && pip install -e ".[dev]" && alembic upgrade head && uvicorn app.main:app --reload
cd frontend && npm install && npm run dev
```

**Проверки перед PR:**
```bash
cd backend && ruff check . && mypy app && pytest
cd frontend && npm run lint && npm run test && npm run build
```
